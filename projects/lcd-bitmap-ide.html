01 / Problem

Embedded HMI development is fragmented across graphics, firmware and documentation.

A small monochrome display can still contain dozens of screens, physical controls, runtime tags, procedures, alarms and navigation rules. When those facts live in separate mockups, spreadsheets and firmware code, the team loses a deterministic source of truth.

LCD Bitmap IDE keeps the visual model, FSM behaviour, text registry, runtime metadata and export settings in one portable .lcdproj project.

03 / Capabilities

One project model across authoring, runtime and automation.

LCD authoring

Text, lines, rectangles, bitmap layers, glyph editing, special UI elements and strict monochrome display bounds.

FSM modelling

Draggable states, global and state-local events, event-labelled transitions, validation and automatic graph layout.

Runtime preview

Step through state flows and validate operator paths before target-hardware handoff.

Screen DSL

Review and edit screen layouts as structured JSON/YAML instead of treating the display as an opaque image.

Embedded exports

C headers, raw frame buffers, XBM, Arduino PROGMEM, Rust embedded-graphics and ESP-IDF-style assets.

REST / MCP

Local-only automation lets developer agents inspect and edit the open project through the same application contract.

The automation boundary stays local. The project README explicitly warns against exposing REST or MCP ports through a public tunnel.

05 / Distribution

Desktop builds for Windows, Linux and macOS.

The repository publishes Tauri and Electron artifacts. Tauri builds are available for Windows, Linux and both Apple Silicon and Intel macOS; Electron remains a stable parallel shell while the Rust/Tauri application evolves.
