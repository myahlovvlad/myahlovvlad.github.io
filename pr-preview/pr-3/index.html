POSITIONING

One engineering path across the full instrument stack.

My strongest work appears at discipline boundaries: when software must reflect physical measurement constraints, embedded behaviour, protocol state and acceptance evidence at the same time.

A / DOMAIN

Measurement first

Start with analytical method, signal path, instrument state, operator sequence and failure modes — then design software.

B / SYSTEM

Explicit behaviour

Represent device state, HMI transitions, hardware actions and measurement workflows explicitly instead of hiding them behind UI screens.

C / EVIDENCE

Verification built in

Connect requirements to physical runs, logs, plots, deviations, root cause, corrective action and retest evidence.
