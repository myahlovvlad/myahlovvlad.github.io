LCD Bitmap IDE

An engineering workbench for turning embedded display layouts, physical controls, device behaviour and multilingual text into one deterministic project model that can be simulated, validated, exported and automated.

GitHub repository ↗Latest releaseProduct screenshots
01 / Problem

Embedded HMI development is fragmented across graphics, firmware, controls and localization.

Even a small monochrome display can contain hundreds of screens and states, physical buttons, runtime tags, alarms, repeated text and navigation rules. When those facts live in separate mockups, spreadsheets and firmware code, the team loses a deterministic source of truth.

LCD Bitmap IDE keeps the visual model, FSM behaviour, physical panel, text registry, runtime metadata and export settings in one portable project.

03 / Capabilities

One project model across authoring, behaviour, localization and automation.

LCD authoring

Pixel-oriented screens, text, lines, rectangles, bitmap layers, glyph editing, reusable templates and explicit display bounds.

FSM modelling

State graph, global and local events, transitions, subsystem views, automatic layout and structural validation.

Physical panel

Model the front panel, place buttons and controls, then bind them to FSM events and detect missing state references.

Text registry

Central RU / EN / ZH text registry, completeness status, import/export and synchronization of repeated strings.

Embedded exports

Firmware-oriented screen assets and universal export paths rather than treating the editor as a mockup-only tool.

REST / MCP

Local automation allows developer agents to inspect and modify the project through an application contract instead of bypassing application state.

04 / Architecture

Deterministic application state is the automation boundary.

The project treats agent access as another controlled client of the same application state. Automation remains local and does not replace deterministic project validation.
