POSITIONING

One engineering path across the full instrument stack.

My strongest work appears at the interfaces between disciplines: when software must reflect physical measurement constraints, embedded interface behaviour, protocol state and acceptance evidence at the same time.

A / DOMAIN

Measurement first

Start with the analytical method, signal path, optics, calibration, operator sequence and failure modes — then design the software.

B / SYSTEM

Explicit behaviour

Represent device state, HMI transitions, blocking operations and measurement workflows explicitly instead of hiding them behind screens.

C / EVIDENCE

Verification built in

Connect requirements to physical runs, logs, plots, deviations, root causes, CAPA and retest evidence.
