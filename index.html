PROFESSIONAL POSITIONING

I engineer the path from a measurement requirement to reproducible instrument behaviour.

My strongest work appears where software cannot be separated from the physical instrument, operator workflow and verification evidence. The deliverable is not only an interface or codebase — it is a controlled system with explicit states, constraints and acceptance logic.

A / DOMAIN

Measurement first

Start from the analytical method, signal path, optics, calibration, operator sequence and failure modes — then design the software.

B / SYSTEM

Explicit behaviour

Model device state, HMI transitions, protocol boundaries, blocking operations and measurement workflows instead of hiding them behind UI screens.

C / EVIDENCE

Verification built in

Connect requirements to instrument runs, logs, plots, deviations, root causes, CAPA and retest evidence.

02 INDUSTRIAL

FIRMWARE / HMI

From static mockups to executable HMI behaviour

Formalized instrument screens, controls, events, states and transitions into an FSM-oriented workflow that can be simulated before firmware handoff. A redesigned behaviour specification was implemented by an OEM partner in the target instrument.

SCREEN→CONTROL→EVENT→STATE→FSM→RUNTIME

OPEN ENGINEERING · PUBLIC

LCD-bitmap IDE

An offline workbench for designing and validating monochrome embedded HMI projects before target-hardware integration.

The public repository combines 128×64 LCD authoring, finite-state-machine navigation, physical button bindings, runtime preview, multilingual text registry, screen DSL, embedded exports and local automation through REST/MCP.
